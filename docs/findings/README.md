# Findings

One file per supported claim, numbered in the order they were established.
Start from [`FINDINGS.md`](../../FINDINGS.md), which lists every claim in one
line with what to do about it.

New findings follow [the template](TEMPLATE.md): a short abstract, the counts,
the claim, the method, then one scope block carrying the caveats and one
statement of what would change the conclusion.

Superseded findings stay in place. [0012](0012-temporal-and-postgresql-pass-development-conformance-not-performance.md)
and [0017](0017-topology-matrix-is-ready-for-pilot-not-publication.md) are kept
because the corrections are part of the record.
